## 四、评分卡设计原则（为什么这么评）

1. **凡是能自动化的一律自动化**——主观项会随时间漂移，3 个月后同一代码的分数应当一致。
2. **扣分项必须打印证据**（文件:行）——评分卡不是排行榜，是**待办清单生成器**。
3. **权重向"曾经痛过的地方"倾斜**——D4（吞错）给 10 分，因为本项目真实因为静默失败排查过数天。
4. **分数不是终点，趋势才是**——每轮评分自动追加历史文件，看的是曲线斜率不是单点值。
5. **门槛写死在脚本里**：A≥85 / B≥70 / C≥55，CI 可直接拿 D1/D2/D4/D6 做硬闸。

## 五、CI 集成建议

在 `.github/workflows/ci.yml` 已有 jobs 之后追加：

```yaml
  quality:
    name: 质量评分卡
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.26', cache: true }
      - run: bash scripts/audit.sh
      - name: 评分不低于 B
        run: |
          score=$(tail -1 .workbuddy/reports/audit-history.txt | cut -d'|' -f2)
          echo "本次评分 $score"
          test "$score" -ge 70
```

> 建议先用 **D1/D2/D4/D6** 做硬闸（这几项任何时候都不该下降），整体评分卡先观察两轮再设闸值。
